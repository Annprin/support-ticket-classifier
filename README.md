# Telco Churn Predictor

ML-проект для прогнозирования оттока клиентов телеком-компании.
Модель реализована в виде нейронной сети (MLP) на PyTorch и оформлена по стандартам Hugging Face (`PreTrainedModel`).

Проект:

* полностью воспроизводим;
* использует **DVC** для версионирования данных и моделей;
* использует **MLflow** для трекинга экспериментов;
* упакован в **Docker-образ** для офлайн-инференса.

---

## 1. Бизнес-цель проекта

Разработка ML-сервиса, который по характеристикам клиента предсказывает вероятность его ухода (churn).

### Бизнес-задачи

* **Идентификация группы риска** — выявление клиентов с высокой вероятностью оттока
* **Таргетированное удержание** — персонализированные предложения только для клиентов группы риска
* **Оптимизация затрат** — снижение расходов на удержание за счёт отказа от массовых скидок

---

## 2. Набор данных

* **Источник:** Telco Customer Churn Dataset (Kaggle)
* **Размер:** ~7 000 клиентов
* **Признаки:** категориальные и числовые
  (`gender`, `SeniorCitizen`, `tenure`, `Contract`, `MonthlyCharges` и др.)
* **Целевая переменная:** `Churn` (Yes / No)

Датасет требует предобработки:

* One-Hot Encoding категориальных признаков
* Масштабирование числовых признаков
* Обработка пропусков

Вся предобработка зашита в DVC-пайплайн.

## 4. DVC-пайплайн

Проект использует DVC-pipeline из трёх стадий:

```text
prepare   →   train   →   evaluate
```

### Стадии

* **prepare** — загрузка и предобработка данных
* **train** — обучение модели и сохранение артефактов
* **evaluate** — валидация модели и сохранение метрик

Пайплайн описан в `dvc.yaml`, все версии зафиксированы в `dvc.lock`.

---

## 5. MLflow: трекинг экспериментов

Для трекинга экспериментов используется **MLflow**.

### Что логируется в MLflow

Каждый запуск обучения (`python -m src.train --config config.yaml`) создаёт отдельный MLflow run со следующими данными:

#### Параметры

* параметры обучения (`epochs`, `learning_rate`, `batch_size`, `random_seed`)
* архитектура модели (`hidden_layers`, `dropout`)
* пути к данным и модели

#### Метрики

* accuracy на валидации
* F1-score для класса Churn
* precision для класса Churn
* train loss (по эпохам)

#### Артефакты

* обученная модель (`models/churn_mlp_model/`)
* `reports/metrics.json`
* `config.yaml`
* `dvc.lock` (для связи эксперимента с версией данных и модели)

Таким образом, каждая версия модели связана:

* с конфигурацией,
* с метриками,
* с версией данных (через DVC).

### Как запустить MLflow UI локально

```bash
mlflow ui --host 127.0.0.1 --port 5000
```

Открой в браузере:

```
http://127.0.0.1:5000
```

## 6. Docker: офлайн-инференс

Проект упакован в Docker-образ для воспроизводимого офлайн-инференса.

### Подготовка модели

Перед сборкой Docker-образа необходимо подтянуть модель и данные через DVC:

```bash
dvc pull
```

### Сборка Docker-образа

```bash
docker build -t ml-app:v1 .
```

### Запуск контейнера

Контейнер запускает офлайн-инференс через `python -m src.predict`.

**Входные данные:**
CSV-файл с сырыми признаками клиента (как в исходном датасете).
Колонка `Churn`, если присутствует, автоматически игнорируется.

**Выходные данные:**
CSV-файл с предсказанным классом и вероятностью оттока.

Пример запуска:

```bash
docker run --rm \
  -v "$(pwd)/sample.csv:/app/input.csv" \
  -v "$(pwd)/outputs:/app/outputs" \
  ml-app:v1 \
  --config config.yaml \
  --input_path /app/input.csv \
  --output_path /app/outputs/preds.csv \
  --proba
```
